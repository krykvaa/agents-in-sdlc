GitHub Copilot をエージェントモードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行を自律的に行います。VS Code の Copilot Chat では、自分のコンピューター上でリアルタイムに実行されるツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、変更を個別に採用または却下できます。エディターを離れずに、追加のプロンプトで会話を誘導し、作業を調整または拡張できます。

この演習では、次の作業を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- 作業中のセッションを誘導し、ハイコントラストモードに加えてライトモードを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントは、ハイコントラストモードを実装しています。作業中に、デザインチームから新たな依頼がありました。デフォルトのテーマが暗すぎると感じる利用者のため、ライトモードの切り替え機能も追加します。新しい会話を始める代わりに、既存のセッションを誘導して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案された編集を確認できます。各ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナルコマンドが表示されます。
3. エージェントがファイルを編集すると、差分がチャットに表示されます。
   - **Keep** を選択して変更を採用します。
   - **Undo** を選択して変更を元に戻し、別の方法で作業するようエージェントに依頼します。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイルをすべて確認できます。

> [!NOTE]
> ターミナルコマンドの実行など、ツールの使用許可を求められると、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に、変更内容の概要が表示されます。

## エージェントを誘導してライトモードを追加する

ハイコントラストモードができたら、同じ会話でライトモードの切り替え機能も追加します。チャットセッションを継続するため、エージェントは前の作業で変更したコンポーネント、スタイルの方法、設定をローカルストレージに保存するパターンをコンテキストとして保持しています。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    いいですね。次は、ハイコントラストの切り替え機能に加えてライトモードも追加してください。ライトモードも同じ方法で実装し、設定をローカルストレージに保存して、同じ UI 領域から利用できるようにしてください。ハイコントラストモードとライトモードは個別に有効化できるようにしてください。
    ```

2. エージェントは既存の変更を調べて、ライトモードの追加を提案します。
3. ハイコントラストモードのときと同じように、新しい編集を確認します。各差分で **Keep** または **Undo** を選択します。
4. エージェントが望まない方向に進んだ場合（たとえば、切り替え UI を意図しない方法でリファクタリングする場合）は、チャット入力欄の横にある **Stop** ボタンで停止してから、追加のメッセージで意図を説明します。

> [!TIP]
> 進行中のセッションを誘導すると、最初からやり直すより速く作業できます。追加のプロンプトで、調整（「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使用する」）、方向修正（「3 つ目の切り替え項目は追加せず、ライトモードを既存の設定パネルに組み込む」）、範囲の拡張（「両方の切り替えにキーボードショートカットも追加する」）を依頼できます。

## 変更されたファイルを確認する

作業をコミットする前に、エージェントが変更した内容を確認しましょう。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧全体を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが指定したアクセシビリティの手法（ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージへの保存）が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージングしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを監視して誘導しました。ファイルの編集を確認しながら採用または却下し、コンテキストを保ったまま追加のプロンプトを送信して作業を拡張しました。

このレッスンでは、次の作業を行いました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を採用または却下する。
- 作業中のセッションに追加のプロンプトを送って誘導する。

[次のレッスン][next-lesson]では、アクセシビリティ作業を pull request として公開し、このラボでローカルのカスタムエージェントが作成した変更をレビューします。
