アプリケーションの簡単な更新でも、通常は複数のファイルを変更し、テストなどの作業を行う必要があります。開発者は、必要なファイルを探し、変更を加え、テストを実行し、問題をデバッグし、変更し忘れたファイルを見つけて、さらに更新することになります。作業は続きます。

Copilot のエージェントモードは、こうした作業を支援します。

エージェントモードは IDE 内で、より自律的に作業できるように設計されています。開発者と同じように、まず既存のプロジェクト構造を調べ、必要な更新を行い、テストなどを実行して、見つかった問題を自動的に修正します。エージェントモードを使ってサイトに機能を追加する方法を確認しましょう。

> [!NOTE]
> 名前は似ていますが、エージェントモードとクラウドエージェントは異なる体験を提供します。エージェントモードは IDE 内で作業するため、すばやくフィードバックを得て対話できます。クラウドエージェントはチームのペアプログラマーとして、issue と pull request を通じてやりとりしながら、非同期に作業します。

この演習では、次のことを学びます。

- Copilot エージェントモードがプロジェクトを調べ、関連ファイルを特定し、複数のファイルにわたって変更を行う方法
- GitHub Copilot エージェントモードが UI とデータレイヤーに新機能を実装する方法
- コードベースにマージする前に、Copilot エージェントモードが生成した変更とテストをレビューする方法

## シナリオ

ゲームの数が増えてきたため、利用者がカテゴリと出版社で絞り込めるようにします。前の演習では出版社ヘルパーを追加しました。次は Copilot エージェントモードを使って、残りのデータレイヤー、UI、テストを完成させます。

## Tailspin Toys の Web サイトを実行する

変更を加える前に、Tailspin Toys の Web サイトを確認し、現在の機能を把握しましょう。

この Web サイトは、開発者をテーマにしたボードゲームのクラウドファンディングプラットフォームです。ゲームの一覧と詳細を表示します。Astro アプリはビルド時にページを静的 HTML として生成します。ページはフロントマターから Drizzle ORM を通じてローカルの SQLite データベースを直接参照します。独立したバックエンド API やクライアント側の UI フレームワークはありません。再利用可能なデータアクセスヘルパーは `src/lib/` にあり、対話機能は標準 DOM API を使った小規模な Astro `<script>` で追加します。

### Web サイトを起動する

Web サイトを簡単に実行できるように、単一の Astro 開発サーバーを起動する `npm run dev` タスクが用意されています。GitHub Codespace で次の手順を実行します。

1. codespace に戻ります。前の演習を完了していれば、`main` に戻っているはずです。
2. <kbd>Control</kbd>+<kbd>`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>`</kbd> (Windows/Linux) を押して、codespace 内に新しいターミナルを開きます。
3. フィルタリング作業用のブランチを作成して切り替えます。

   ```bash
   git checkout main
   git pull
   git checkout -b filtering-vscode
   ```

4. 次のコマンドを実行して Web サイトを起動します。

   ```bash
   npm run dev
   ```

   Astro 開発サーバーの準備ができると、次のような URL を示すメッセージが表示されます。

   ```bash
   🚀 Tailspin Toys is ready!
      Astro server: http://localhost:4321
      Press Ctrl-C to stop.
   ```

> [!NOTE]
> `http://localhost:4321` を開くよう促すダイアログが表示された場合は、**x** を選択して閉じます。

5. ターミナルで Astro サーバーのアドレス `http://localhost:4321` を選択します。Mac では <kbd>Command</kbd>、Windows/Linux では <kbd>Ctrl</kbd> を押しながら選択してください。

> [!NOTE]
> codespace のターミナルから localhost URL を選択すると、自動的に `https://<your-codespace-name>-4321.app.github.dev/` に転送されます。これは、Web サーバーを実行する codespace へのプライベートトンネルです。

### Web サイトを確認する

Web サイトが起動したら、機能を確認します。主な機能は次のとおりです。

- **ホームページ**: ボードゲームのタイトル、画像、説明を一覧表示します。
- **ゲームの詳細ページ**: ゲームを選択すると、タイトル、説明、出版社、カテゴリなどを含む詳細ページが表示されます。

## Copilot でバックログを確認する

> [!TIP]
> **Copilot Chat を開く**
>
> 次の演習を始める前に、codespace に戻り、Copilot Chat パネルを開き、**New Chat** を選択して新しい会話を始めます。モードとモデルの選択は演習ごとに異なります。必要な場合は各手順で説明します。

Web サイトは動作しますが、新しい機能を追加して改善しましょう。まずバックログを確認します。テンプレートからプロジェクトを設定すると issue のバックログが自動的に作成されるため、GitHub Copilot に内容を表示するよう依頼します。

1. Chat ビューのエージェントのドロップダウンから **Agent** を選択します。**Agent** はファイルにまたがる変更を自律的に計画・実装し、ターミナルコマンドを実行してツールを呼び出します。

   ![Chat ビューでエージェントを選択する画面](../../../_images/shared-chat-mode-selector.png)

2. 使用可能なモデルの一覧から **Claude Sonnet 4.5** を選択します。

> [!CAUTION]
> このワークショップの作成者は、特定のモデルを推奨する意図はありません。ワークショップの作成には Claude Sonnet 4.5 を使用したため、手順にも記載しています。提案の一貫性を高め、スムーズに学習できるようにするためです。ただし、大規模言語モデル (LLM) は確率的に動作するため、ワークショップの説明と異なる提案が表示されることがあります。これは通常の動作です。

> [!NOTE]
> LLM の確率的な性質により、Copilot が別の MCP コマンドを使用する場合があります。その場合でも、タスクを完了できるはずです。

3. 次のプロンプトを Copilot に送信して、バックログの issue を確認します。

   ```plaintext
   GitHub リポジトリのバックログを表示してください。利用者にとって最も役立つ項目を優先して、優先順位付けを手伝ってください。
   ```

4. **Continue** を選択して、すべての issue を一覧表示するコマンドを実行します。
5. 生成された issue の一覧を確認します。

Copilot が、利用者にとって役に立つと思われる項目を優先順位付けしたことを確認できます。

## 指示ファイルを確認する

エージェントにコードを生成してもらう前に、Copilot にコンテキストを提供する指示ファイルを確認しましょう。Web サイトに機能を追加する方法を説明する [UI 指示ファイル](https://github.com/github-samples/tailspin-toys/blob/main/.github/instructions/ui.instructions.md)を使用します。

1. codespace で `.github/instructions/ui.instructions.md` に移動します。
2. 機能を追加するための全般的なガイダンスを確認します。次の内容が含まれます。
   - アーキテクチャの概要
   - コンポーネント設計、テスト容易性、アクセシビリティの原則
   - さまざまなファイル形式に対応する指示ファイルへのリンク:
     - Astro
     - Tailwind CSS
     - Drizzle

> [!TIP]
> 指示ファイルから、他の指示ファイルやプロジェクト内のファイルを参照できます。パスは指示ファイルの場所からの相対パスです。指示を再利用し、複雑な内容を扱いやすい小さなファイルに分け、例やひな形を示せます。

## フィルタリング機能を実装する

フィルタリング機能を完成させるには、少なくとも次の 3 つを更新する必要があります。

- データレイヤー (`src/lib/`) にフィルタリングロジックを追加または調整します。
- フィルタリングの動作を確認するテストを追加または更新します。
- ゲーム一覧ページにフィルタリング UI を追加します。

コードベースにマージする前にテストを実行し、成功する必要があります。Copilot エージェントモードに作業を依頼しましょう。

1. Copilot との現在の会話を続けるか、**New Chat** を選択して新しい会話を始めます。
2. **Add Context**、**Instructions**、**ui** の順に選択して、UI 指示ファイルを指定します。

   ![UI 指示ファイルを選択する例](../../../_images/ex3-select-instructions-file.png)

3. Chat ビューのエージェントのドロップダウンで、引き続き **Agent** が選択されていることを確認します。

   ![Chat ビューでエージェントを選択する画面](../../../_images/shared-chat-mode-selector.png)

4. モデルが引き続き **Claude Sonnet 4.5** に設定されていることを確認します。
5. バックログにある関連 issue の要件に基づいて機能を実装するよう、次のプロンプトを使って Copilot に依頼します。

   ```plaintext
   バックログにある関連 GitHub issue の要件に基づいて、出版社とカテゴリによるフィルタリングをサイトに追加してください。前の演習で出版社ヘルパーを作成済みです。必要に応じてその作業を維持・改善しながら、残りのデータレイヤー、UI、テストを完成させてください。完了前にすべてのテストが成功することを確認してください。サーバーはすでに実行中なので、起動する必要はありません。
   ```

6. Copilot がプロジェクトを調べ、機能に関係するファイルを探す様子を確認します。データレイヤーのヘルパー、UI、テストを特定し、ファイルの変更とテストの実行を始めます。

   ![Copilot がプロジェクトのファイルを調べる画面](../../../_images/ex3-agent-mode-explores.png)

> [!NOTE]
> Copilot はプロジェクトを調べ、ファイルを変更し、テストを実行します。タスクやコードベースの複雑さによっては、数分かかります。作業中、コードエディターに **Keep** と **Undo** が表示される場合があります。作業が完了すると、すべての変更に対して **Keep** または **Undo** が表示されるため、作業中に選択する必要はありません。

7. Copilot に求められたら、**Continue** を選択してテストを実行します。

   ![テストを実行してよいか確認する Copilot Chat のダイアログ](../../../_images/ex3-agent-mode-run-tests.png)

8. 作業中に一時停止したり、テストに失敗したりすることがあります。問題ありません。Copilot はコード生成とテストを繰り返し、タスクが完了してエラーを検出しなくなるまで修正します。

   ![Copilot エージェントモードの完了したチャットセッション](../../../_images/ex3-agent-mode-proposed-changes.png)

9. 生成されたコードに問題がないか確認します。

> [!CAUTION]
> Copilot などの AI ツールが生成したコードは、必ずレビューしてください。

10. Web サイトを表示しているブラウザーに戻り、新機能を確認します。
11. 動作とコードを確認したら、Copilot Chat ウィンドウで **Keep** を選択します。

## まとめと次のステップ

この演習では、GitHub Copilot エージェントモードを使って Tailspin Toys の Web サイトに機能を追加する方法を学びました。

- GitHub Copilot エージェントモードで UI とデータレイヤーに新機能を実装しました。
- エージェントモードがプロジェクトを調べ、関連ファイルを特定し、連携した変更を行う様子を確認しました。
- コードベースにマージする前に、生成された変更とテストをレビューしました。

次は [Playwright MCP サーバーで機能をテスト][next-lesson]し、pull request を作成しましょう。

### 発展演習 — ページ分割を実装する

ゲームの一覧が増えるとページ分割が必要になります。この演習で学んだスキルを使い、Copilot にページ分割の実装を依頼します。次の点を検討してください。

- 既存の指示ファイルを使うなど、現在のベストプラクティスに従います。
- 利用者がページサイズを選べるようにするか、値を固定するかなど、ページ分割の方法を検討します。
- 希望する実装に必要なガイダンスをプロンプトで Copilot に伝えます。
- Copilot に変更やコンテキストを伝え、反復的に改善する必要がある場合があります。これは Copilot を使う通常のワークフローです。
