使用智能体模式时，GitHub Copilot 会自主探索代码库、提出更改、编辑文件并运行命令。由于 Copilot 会在您的计算机上实时工作，VS Code 中的 Copilot Chat 会持续显示每次工具调用和文件编辑。您可以内联审查每项差异、接受或拒绝单项更改，也可以通过后续提示引导对话、改进或扩展工作，全程无需离开编辑器。

本练习将完成以下任务：

- 实时监控无障碍访问智能体的工作。
- 审查并接受建议的文件编辑。
- 在会话进行期间引导智能体，在高对比度模式之外添加浅色模式切换开关。

## 场景

您在[练习 4][previous-lesson]中使用的无障碍访问自定义智能体正在实现高对比度模式。工作进行期间，设计团队提出了额外需求：为觉得默认主题太暗的用户添加浅色模式切换开关。无需从头开始新对话，您可以引导当前会话扩展工作内容。

## 监控 Copilot 的进度

Copilot Chat 视图会显示智能体执行的每个步骤，包括探索的文件、运行的命令和提出的编辑。每项文件编辑都会在聊天中内联显示差异和 **Keep** / **Undo** 控件。

1. 返回练习 4 中的 Copilot Chat 视图。
2. 智能体工作时，滚动聊天内容，查看每次工具调用。您会看到文件读取、文件编辑以及需要运行的终端命令。
3. 智能体提出文件编辑时，差异会内联显示：
    - 选择 **Keep** 接受更改。
    - 选择 **Undo** 撤销更改，让智能体重新尝试。
4. 也可以打开聊天顶部的 **Files changed** 指示器，查看智能体在本次会话中修改的所有文件。

> [!NOTE]
> 如果工具调用需要权限（例如运行终端命令），智能体会暂停并显示 **Allow** 提示。只批准您信任的命令。

5. 等待智能体完成高对比度模式。它应该会发送一条总结所做更改的最终消息。

## 引导智能体添加浅色模式

高对比度模式就绪后，扩展当前对话，添加浅色模式切换开关。由于继续使用同一聊天会话，智能体会保留先前工作的上下文，包括修改的组件、使用的样式方案和设置的 local storage 模式。

1. 在 Copilot Chat 输入框中发送以下后续提示：

    ```plaintext
    做得很好！现在请在高对比度开关旁添加浅色模式切换开关。浅色模式应采用相同模式——通过 local storage 保存设置，并在 UI 的同一区域提供入口。用户应能分别启用高对比度模式和浅色模式。
    ```

2. 智能体会从先前工作继续，探索已有更改并提出浅色模式的新增内容。
3. 新编辑加入时逐项审查，就像处理高对比度模式时一样。对每项差异使用 **Keep** 或 **Undo**。
4. 如果智能体的实现方向不符合预期（例如尝试以不喜欢的方式重构开关 UI），可以选择聊天输入框旁的 **Stop** 按钮停止任务，然后发送澄清提示。

> [!TIP]
> 引导正在进行的会话比从头开始更快。可以使用后续提示要求调整（“简化 CSS，改用 CSS 变量，不要重复选择器”）、纠正方向（“不要添加第三个开关，将浅色模式并入现有设置面板”）或扩展范围（“为两个开关都添加键盘快捷键”）。

## 审查工作集

提交更改前，快速检查智能体修改的所有内容。

1. 在 VS Code 中打开 **Source Control** 视图。
2. 审查所有已更改文件。应该会看到 Astro 组件、样式和相关测试的更新。
3. 打开几个已更改的文件并查看差异。确认其中体现了自定义智能体要求的无障碍模式，包括 ARIA 属性、键盘导航、语义化 HTML 和通过 local storage 保存设置。
4. 确认满意后，在 Source Control 面板中暂存并提交更改。您将在[下一课][next-lesson]中发布这些更改。

## 总结和后续步骤

您使用 Copilot Chat 智能体模式监控并引导正在进行的会话，逐项审查文件编辑、接受或拒绝更改，并通过后续提示扩展工作，同时保留上下文。

本课介绍了以下内容：

- 实时监控智能体工作。
- 接受或拒绝单项文件编辑。
- 通过后续提示引导正在进行的会话。

在[下一课][next-lesson]中，您将把无障碍访问工作发布为拉取请求，并审查本实验中本地自定义智能体生成的更改。
